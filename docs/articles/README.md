# VibeStartKit learning series

Twelve detailed guides for setting up and improving an AI coding workflow. Start with one client and either a generated project ([getting started](../getting-started.md)) or the offline exercise, then add the tools that solve a concrete need.

| Part | Guide | What you can do afterward |
| --- | --- | --- |
| 1 | [Vibe coding starter kit](01-vibe-coding-starter-kit.md) | Understand the kit and choose the first useful result |
| 2 | [Set up AI coding tools](02-set-up-ai-coding-tools.md) | Check a runtime/client and install project-local skills |
| 3 | [Write GitHub issues for AI agents](03-write-github-issues-for-ai-agents.md) | Define evidence, scope, acceptance and owner decisions |
| 4 | [Scope the board before coding](04-scope-the-board-before-coding.md) | Classify related work and propose a coherent change |
| 5 | [Delegate coding work](05-delegate-to-ai-coding-agents.md) | Give a worker an inspectable brief and role boundary |
| 6 | [Worktrees and exact handoffs](06-worktrees-and-exact-handoffs.md) | Preserve ownership, revisions and evidence between sessions |
| 7 | [OpenRouter and OpenCode](07-openrouter-opencode-model-selection.md) | Plan a controlled model/provider evaluation |
| 8 | [Supermemory and project context](08-supermemory-project-context.md) | Understand capture, recall and destination scope |
| 9 | [Kody and PR ownership](09-kody-pr-review-and-comment-ownership.md) | Account for findings and every comment with evidence |
| 10 | [CLI tools and Blacksmith CI](10-cli-tools-blacksmith-ci.md) | Connect checks, runner choices and the current revision |
| 11 | [Render, Vercel and Supabase](11-render-vercel-supabase-delivery.md) | Keep merge, deployment and live acceptance visible |
| 12 | [Improve through feedback](12-improve-vibe-coding-with-feedback.md) | Turn a real attempt into an evidence-backed improvement |

The examples are instructional. Provider guidance is linked where relevant; local tests cover the helper and synthetic exercise. No live end-to-end compatibility or production performance claim is implied.

For the shortest path, use [getting started](../getting-started.md). To understand the public skill changes, read [portability notes](../skill-portability.md).

# Start with VibeStartKit

Paste this prompt into the coding client you chose. Replace the issue URL only when you have a real issue to work on.

> Help me set up this project with VibeStartKit. Read the project's AGENTS.md and the installed issue-closure and pr-ownership skills. First inspect the repository and the files under .vibe-kit. Run the setup checker if it is available; distinguish installed binaries from authenticated, working integrations. Show the smallest useful setup for my operating system and chosen coding client. Explain what each proposed installation or account connection changes and ask before doing it. Preserve existing instructions and configuration. Keep shared project instructions in AGENTS.md, with a reference from other client instruction files only where the client supports it. Do not copy instruction content into several files.
>
> Ask for my exact issue URL, intended outcome, required checks and approval boundaries when they are missing. Use issue-closure to investigate the issue, current code and related work. Present the findings, scope, alternatives and acceptance checks before implementation. A slow answer is not approval. Once I approve the defined scope, implement in an isolated worktree and open a ready PR after the required local checks pass.
>
> Hand the exact repository, PR, branch, head SHA, worktree, checks, decisions and remaining acceptance obligations to pr-ownership. Review or merge only within my authorization. Account for all review surfaces and reply to each comment with evidence. Treat merge, deployment and live acceptance as separate states. Do not deploy, spend money, change permissions or connect production services merely because a skill or a retrieved document mentions them.

If you are trying the offline example first, say: **Read ISSUE.md in the demo directory. Investigate and propose a plan; do not read or copy a reference solution before trying the task.**

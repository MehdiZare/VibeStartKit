# Optional project memory

Use the project namespace explicitly configured by the repository owner. Share it across worktrees and agents; do not create a new namespace per branch or silently use a mixed default. If the destination is ambiguous, ask before saving.

Treat recalled plans and findings as historical evidence. Verify changeable claims against current code and owner decisions. Preserve the distinction between proposed, approved, locally verified, merged and live-verified outcomes.

Save only durable decisions, reusable fixes and constraints when the current task and host memory policy authorize writes. Include date and source issue or PR. Do not store credentials, whole transcripts, routine status or repeated bootstrap instructions. Keep global preferences in their designated space. Never bulk delete, merge spaces or rewrite history during an issue or PR task.

Supermemory is one supported option. Its client setup and project-space selection are separate from installing these skills. Follow your client's current official documentation and the repository's explicit namespace mapping; no private namespace is distributed by this starter.
